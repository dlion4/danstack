Business-Dashboard — All Error & Warning Variants

Every item from your list built as standalone advanced page (cream #FFFCF5, emerald #10b981, red #EF4444). Separated by UX pattern: Warning Modal (Before Action) needs permission checkbox → then action. Error Full-Page (After Failure) shows after send & wait few seconds → fails. Info Hold = queued review.
How to use each:
• WARNING Modal → In-page popup. Trigger when user clicks "Send/Pay/Create". Requires tick "I understand risk" + Confirm. No money moved yet. Example: AP-002 Maker-Checker, BULK-003 Limit Exceeded, VA-001 Limit Reached.
• ERROR Full-Page → User sent money, waited few seconds (spinner), then payment fails → show full error page with trace + retry. Example: TR-001 Insufficient Float, COLL-001 Till Inactive, PAY-002 PAYE Mismatch.
• INFO HOLD → After send, goes to review queue (processing-hold twin). Shows timer, steps. Example: BUS-KYC-002 Under Review.

Integration Guide — Modal vs Full-Page
WARNING modal (before action): Trigger on button click → show modal with permission checkbox (I understand risk) → Confirm → then call API. All warning pages include #confirmCheck checkbox + toast "Confirmed". Use for AP-002, AP-004, BULK-003, VA-001, SET-001, etc.

ERROR full-page (after failure): User already clicked Send → show spinner 2-3s → API returns error → navigate to error page variant we built. Shows trace ID, no double-charge guard, retry. Use for TR-001 Insufficient Float, COLL-001 Till Inactive, PAY-002 PAYE Mismatch, etc.

INFO HOLD: After send, status = VERIFYING → show hold page like processing-hold with elapsed ticker + ETA + vault safe. Use for BUS-KYC-002 Under Review.

All pages already have same design system: cream #FFFCF5, emerald gradient btn, red/amber/blue accents, toast top-right, info modal blurred, mobile responsive with full-width buttons.
